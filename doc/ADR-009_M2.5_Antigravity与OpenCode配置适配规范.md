# ADR-009：M2.5 Antigravity / OpenCode MCP 配置适配规范

- 状态：**提议采用**
- 日期：2026-11-20
- 决策范围：Gateway GUI 自动配置 MCP Host
- 关联：ADR-007、M2.5 GUI 管理与配置交互规范

## 1. 目标

由 AirBridge GUI 自动添加、更新、验证和移除 AirBridge MCP Server 配置。不得要求普通用户手工编辑 MCP JSON，不得损坏既有 MCP Server 或用户配置。

配置适配必须依据客户端类型、实际安装版本、配置文件路径和 schema。不得假设两个客户端使用同一种 JSON 结构。

## 2. Antigravity Adapter

官方文档确认：
- Antigravity App 可在 Customizations → Installed → MCP Servers 中管理配置，并提供 Copy Config File Path；
- Antigravity CLI 全局配置：`~/.gemini/config/mcp_config.json`；
- CLI 工作区配置：`<workspace>/.agents/mcp_config.json`；
- App / IDE / CLI 采用 `mcpServers` 根对象；
- 远程 Streamable HTTP 字段为 `serverUrl`；
- 支持 `headers`、`disabled`、`timeoutSeconds` 等字段；
- OAuth 支持 PKCE、CIMD、DCR；IDE 的 CIMD 支持要求 2.6.0+。

配置 Adapter 规则：
1. 对 Antigravity App 优先通过 GUI/官方界面可见的实际配置路径发现机制，不能硬编码单一 App 路径。
2. 对 CLI 可提供 global / workspace 两种安装范围，默认选择 global；工作区级写入必须由用户明确选择。
3. 只修改 `mcpServers.airbridge-<agent>` 对应条目。
4. 写入前验证 `mcpServers` 类型正确，现有条目结构可解析。
5. 不写入 M2.4 Agent Service Token。
6. OAuth 不兼容或客户端版本过低时，显示兼容性提示，不回退为明文 Header Token。
7. Antigravity App 的 OAuth 授权可能需要用户在客户端 UI 中完成确认；AirBridge GUI 不假设可以替代该授权交互。

## 3. OpenCode Adapter

官方文档确认：
- Remote MCP 配置采用 `mcp.servers.<name>`；
- Remote Server 需要 `type: "remote"` 和绝对 `url`；
- OAuth 默认启用；`oauth: false` 用于明确选择 Header/API Key 模式；
- JSON 与 JSONC 均受支持；
- 用户全局配置为 `~/.config/opencode/opencode.json(c)`；
- Windows 系统级配置目录为 `%ProgramData%\opencode`；
- 项目级还可能存在 `opencode.json(c)` 或 `.opencode/opencode.json(c)`；
- 配置具有多层优先级，较高优先级文件可能覆盖同名 MCP server 对象。

配置 Adapter 规则：
1. 默认只修改当前 Windows 用户全局配置，不写入项目仓库。
2. 系统级配置需要管理员权限，未获得用户明确授权时不修改。
3. 项目配置发现后只提示，不自动把机器级 Gateway 写入项目。
4. 使用 `mcp.servers.airbridge-<agent>` 唯一名字。
5. 确保写入 `type="remote"` 和 `url`。
6. 不设置 `oauth: false`，让支持的客户端走标准 OAuth 授权。
7. 尊重客户端版本的 schema；当前 OpenCode V2 配置不应继续套用旧版顶层 MCP 结构。

## 4. 配置文件安全更新

通用规则：
- 先识别客户端版本和 schema，再决定配置目标路径；
- 不猜路径、不递归扫描用户所有工程后静默修改；
- 修改前读取完整配置并生成可恢复备份；
- 采用 JSON / JSONC 感知解析器；
- 保留所有未管理的 MCP Server 和未知字段；
- 对同名 AirBridge Server 采用明确的更新策略，不重复添加；
- 对 JSONC 注释和格式尽可能保持；若当前解析器无法安全保留注释，应明确提示并保存原始备份；
- 使用临时文件 + 原子替换；
- 写入后重新解析并校验；
- 任何阶段失败都恢复原始文件或保持原文件不动；
- 不将 Access Token、Refresh Token、M2.4 Service Token 或客户端 Secret 写入配置；
- 移除 AirBridge 项时只删除明确归属的 AirBridge 条目，不删除其他服务。

## 5. 安装范围和多配置冲突

同一个 MCP Host 可能同时存在全局配置、系统级配置、项目配置或应用内生成配置。Adapter 必须展示实际发现的路径和优先级，不应在多个配置层重复写入。

建议默认策略：
- Antigravity App：使用其自身实际配置路径；
- Antigravity CLI：用户全局配置；
- OpenCode：用户全局配置；
- 系统配置和项目配置：只读发现，除非用户主动选择目标。

若同名 Server 在多个配置层出现，应显示冲突和覆盖优先级，不擅自清理用户项目配置。

## 6. 连接诊断

每个 Adapter 提供：
- 配置文件路径发现；
- 配置读取权限检查；
- schema / JSONC 解析；
- AirBridge 条目检查；
- endpoint 请求检查；
- OAuth 授权状态检查（只显示状态，不显示 Token）；
- MCP initialize；
- tools/list；
- 指定只读 Tool 调用。

连接诊断不得调用 EDA Execute、Shell Execute 或文件写入工具。

## 7. 验收

- [ ] 能识别目标客户端产品与版本。
- [ ] 能找到实际配置路径，并在 GUI 显示路径来源。
- [ ] Antigravity 写入 `mcpServers` 结构。
- [ ] OpenCode 写入 V2 `mcp.servers` 结构。
- [ ] 其他 MCP Server 保留。
- [ ] JSONC 格式和未知字段安全保留。
- [ ] 写入失败不破坏原文件。
- [ ] 配置中无任何 M2.4 Agent Service Token / OAuth Token。
- [ ] 同名配置只更新一次。
- [ ] 全局 / 系统 / 工作区层级的优先级冲突能被识别。
- [ ] 客户端重启/Reload 后真实连接并成功执行只读诊断。

## 9. 2026-11-20 OAuth 用户交互与 HTTPS 修订（v0.2）

### 9.1 MCP endpoint 使用 HTTPS

托管模式配置写入的是每 Agent 的 HTTPS Resource Server URL，例如：

```json
{
  "mcpServers": {
    "airbridge-antigravity": {
      "serverUrl": "https://localhost:<assigned-port>/mcp"
    }
  }
}
```

```json
{
  "mcp": {
    "servers": {
      "airbridge-opencode": {
        "type": "remote",
        "url": "https://localhost:<assigned-port>/mcp"
      }
    }
  }
}
```

端口由 AirBridge 配置管理器分配；不得将上例尖括号内容写进实际 JSON。证书 SAN 必须覆盖实际使用的 loopback hostname / IP，且目标客户端必须正常验证证书链。

### 9.2 Antigravity OAuth 是客户端自己的交互流程

官方文档说明，Antigravity App / IDE 的认证流程由客户端发起：
1. 用户在 Customizations / Installed / MCP Servers 页面找到 AirBridge；
2. 点击 Authenticate；
3. 在浏览器完成授权；
4. 根据客户端界面提交授权码；
5. 客户端连接并自行保存 / 刷新 OAuth Token。

官方当前文档指出客户端会将 OAuth Token 存在它自己的用户目录中（例如 `~/.gemini/antigravity/mcp_oauth_tokens.json`）。AirBridge Adapter 不得读取、复制、备份、改写或删除此文件。

GUI 负责配置写入、打开客户端设置页面和授权引导；不能假装自己替 Antigravity 完成授权。

### 9.3 OpenCode OAuth 是客户端自己的交互流程

OpenCode 官方文档提供：
- UI 中使用 `/mcps` 选择 Server 并登录；
- CLI 使用 `opencode mcp auth <server-name>` 开始授权；
- `opencode mcp logout <server-name>` 可清理 OpenCode 自身保存的授权。

AirBridge GUI 可以在确认 OpenCode CLI 路径和版本后提供可选的“启动 OpenCode 授权”快捷操作；CLI 不存在时显示 `/mcps` 操作说明。AirBridge 不读写 OpenCode 私有 OAuth Token 存储。

### 9.4 授权状态不等于配置状态

Adapter 必须分别提供：
- 配置文件存在且 schema 合法；
- endpoint HTTPS 可达且证书可信；
- OAuth Broker 已签发 Grant；
- Worker 最近是否收到成功认证的 MCP 请求；
- initialize / tools/list / read-only tool test 结果。

MCP Client 的 Token Vault 由客户端自己管理。AirBridge 可显示 Broker Grant 和 Worker 观察到的成功请求，但不得只凭配置文件写入成功显示“客户端已授权”。

### 9.5 OpenCode 配置优先级与协议版本

- 默认写入用户全局配置；
- 项目级配置可能整体替换同名 Server 对象，因此为 AirBridge 使用稳定且唯一的 server name，发现同名覆盖时在 GUI 明示；
- OpenCode 当前默认使用 classic MCP initialize handshake。M2.5 Gateway 首版应省略 `protocol` 字段或显式设置 `legacy`，不要在 SDK / Server 未实现新版协议前写入 `2026-07-28`；
- 不要设置 `oauth: false`，除非未来另行通过安全评审采用非 OAuth 认证方案。

### 9.6 OAuth 客户端注册策略（D-07，用户已确认）

M2.5 首批客户端注册采用“官方 CIMD 白名单优先 + DCR 兼容回退”：
- Antigravity 精确 Client ID Metadata URL：`https://antigravity.google/oauth/client-metadata.json`。IDE CIMD 要求 2.6.0+；旧版本 / 未采用 CIMD 的受支持版本走 DCR fallback。官方 CIMD redirect URI 为 `https://antigravity.google/oauth-callback`。
- OpenCode 精确 Client ID Metadata URL：`https://opencode.ai/oauth/opencode/client.json`。Authorization Server 声明支持 CIMD 且客户端未设置自定义 `redirect_uri` 时，OpenCode 使用 CIMD；设置自定义 redirect URI 会回退 DCR。
- Authorization Server metadata 提供稳定、非空的 issuer、`code_challenge_methods_supported=["S256"]` 和 public client 支持（`token_endpoint_auth_methods_supported=["none"]`）；兼容时声明 `client_id_metadata_document_supported=true`，同时保留 DCR registration endpoint。AirBridge Adapter 不写入 `oauth.client_id`、`oauth.client_secret` 或自定义 `redirect_uri`，避免绕过客户端官方发现优先级。
- 若现有 AirBridge Server 条目含用户手动设置的 Antigravity `oauth.clientId/clientSecret` 或 OpenCode `oauth.client_id/client_secret/redirect_uri`，Adapter 必须识别并提示它们可能覆盖 / 禁用 CIMD 优先行为；不得静默删除或覆盖用户字段。只有用户明确移除后，才能走标准 CIMD 优先流程。
- CIMD URL 必须与上述完整 URL 精确匹配；不接受任意 URL、通配域名、用户自定义地址、query / fragment、非标准端口或跨域重定向。优先预登记可信 Client ID 与官方 redirect URI，不为任意 URL 发起 metadata fetch。
- DCR 只作为首批两个客户端的协议兼容回退，不代表支持通用 MCP Client。DCR 客户端提供的名称、网站、图标和产品声明均是不可信输入，不可用来证明客户端确实来自 Antigravity / OpenCode。
- DCR endpoint 只接受受支持的公共授权码客户端；强制 PKCE S256，校验 redirect URI、grant / response type 和 token endpoint auth method；限制注册速率、数量、元数据大小，并记录审计。
- OpenCode CIMD loopback callback 必须遵守其官方 metadata 和 RFC 8252 规则。动态 callback port 不等于允许任意 host / scheme / path；每次授权请求的实际 redirect URI 必须严格校验。
- DCR / CIMD 注册成功只建立 OAuth Client Registration，不创建 Grant、不授予 Agent Scope、不允许调用 MCP Tools。任何 Grant 都必须经用户 Consent，并精确绑定 Client ID、Agent instance、Resource Audience 和 Scope。一个 Client ID 请求不同 Agent / Resource 时必须分别授权；白名单本身不构成自动授权。

不得开启任意 CIMD URL 抓取。精确白名单意味着本项目不需要通过任意 metadata URL fetch 实现通用客户端支持，也不应引入额外 SSRF 攻击面。仅有 DCR / CIMD 注册不能授予 Agent 权限。

### 9.7 升级时的 MCP 配置保留与迁移（D-01）

升级安装时，Adapter 必须：
- 保留当前用户级 AirBridge Server 条目及有效 endpoint；若版本变更要求调整，只更新明确归属 AirBridge 的条目。
- 修改前保存原始配置备份；仅对当前用户级文件执行迁移，不写入项目级或系统级配置。
- 保留其他 MCP Server、未知字段、JSONC 注释 / 格式和用户自定义选项；不得重写整个文件来达到局部更新目的。
- 使用版本化、幂等的配置迁移；解析失败、未知 schema 或写入验证失败时，原文件保持不变并提供备份恢复路径，不得静默创建空配置覆盖旧文件。
- 同名 AirBridge 条目更新时不创建重复项；不再兼容的旧字段需要在 GUI 说明迁移内容，未经用户明确选择不得清理无关条目。

**OAuth 状态边界：**
- Antigravity / OpenCode 的 Access Token / Refresh Token Vault 始终由客户端管理。Adapter 不读取、复制、备份、迁移、改写或删除客户端 Token Vault。
- 正常升级保持现有 HTTPS endpoint 和 OAuth issuer / Resource Audience 不变，避免无故触发重新授权。
- 若产品版本变化确实需要更改 endpoint / issuer / audience，GUI 必须显示受影响的 Agent、原因和重新授权步骤；不得通过读取或复制客户端 Token Vault 来“迁移授权”。
