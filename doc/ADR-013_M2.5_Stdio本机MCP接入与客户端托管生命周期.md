# ADR-013：M2.5 STDIO 本机 MCP 接入与客户端托管生命周期

- 文档编号：AB-M2.5-ADR-013
- 版本：0.1
- 日期：2026-11-20
- 状态：**用户已确认采用；M2.5 首版强制架构决策**
- 取代：ADR-007 的 Streamable HTTP / OAuth 方案、ADR-010 的本机 OAuth Broker / HTTPS 方案，以及旧 v0.3 文档中冲突的 Managed HTTPS / CA / OAuth Worker 设计
- 范围：M2.5 首批 Antigravity、OpenCode 两个专用 MCP Client Adapter

## 1. 决策摘要

M2.5 首版只使用**本机 MCP STDIO transport**。Antigravity / OpenCode 通过各自 MCP 配置启动本机统一程序 AirBridge.exe 的 STDIO 子进程；MCP 消息通过操作系统创建的 stdin / stdout 管道传递。

**不使用证书，不建立面向 MCP Client 的 HTTP / HTTPS endpoint，不实现 OAuth Broker。**

直接取消：
- Streamable HTTP、SSE、WebSocket 等 MCP 网络 transport；
- 本机 localhost HTTP / HTTPS listener、端口分配和端口冲突管理；
- TLS、CA 生成 / 分发 / 安装、CurrentUser Root 信任、CryptUIWizImport；
- MCP OAuth Authorization Server、OAuth Access / Refresh Token、PKCE、CIMD、DCR、OAuth Consent；
- Broker / Resource Server 双 HTTPS、Resource Audience 和网络 Token Introspection；
- 为上述 TLS / OAuth 方案建设的 G-01 Windows 证书 PoC、CI 脚本和 Self-hosted Runner。

本决策不改变：
- Host A ↔ Host B 之间现有 AirBridge ABFP / 串口通信；
- M2.4 Agent Bearer Service Token、Credential Provider / Windows Credential Manager、Scope、请求归属、撤销、限流和审计；
- 主机 A / B 使用相同 AirBridge.exe、相同安装包和相同完整功能；
- 首次安装 Gateway 默认 OFF；
- 首批专用 Adapter 只有 Antigravity 和 OpenCode；
- AirBridge Core 仍是通用透明通信通道；Capture / Allegro 生命周期属于对应 Skill。

## 2. 官方客户端兼容性依据

### 2.1 Antigravity

Google 官方 MCP 配置使用 mcpServers。本机 STDIO 条目使用 command 启动可执行程序，并可使用 args、env、cwd 和 disabled。远程连接才使用 serverUrl。

- https://antigravity.google/docs/ide-mcp
- https://antigravity.google/docs/mcp

### 2.2 OpenCode

OpenCode V2 官方配置使用 mcp.servers.<name>。本机 STDIO 条目使用 type: "local" 和 command: string[]；客户端负责启动并管理该本地进程。远程连接才使用 type: "remote" 和 URL。

- https://opencode.ai/docs/mcp-servers/

### 2.3 兼容性边界

上述官方文档证明两个目标客户端都提供本机 STDIO 配置入口。实际支持矩阵仍须在首版冻结的 Antigravity App / IDE 与 OpenCode 版本上完成真实 initialize、tools/list 和只读 Tool 调用验收。不能把远程 OAuth / HTTPS 能力当作 STDIO 的前置条件。

## 3. 目标拓扑

### 3.1 已有 STDIO 实现基线

当前 main 已有 M2.1 / M2.2 本机 STDIO Gateway：mcp_gateway/airbridge_mcp_gateway/server.py 使用 MCP Python SDK 的 stdio transport；service.py 将通用 Tool 映射到现有 AirBridge HTTP API；config.py 从 AIRBRIDGE_AGENT_ID 读取非秘密 Agent 标识并通过 Credential Provider 加载当前 Windows 用户 Credential Manager 中对应的 Token；credential_store.py 提供 Windows Credential Manager 实现；tests/test_mcp_server.py、test_gateway.py 和 test_credential_store.py 已有基础单元测试。

当前实现仍作为独立 mcp_gateway Python 包 / 虚拟环境运行。M2.5 的方向不是重新发明 STDIO Server，而是将这套已有的 STDIO Server、配置、Credential Provider 和测试纳入统一 AirBridge.exe / Python 3.11+ 构建，去除独立虚拟环境部署，并补齐 GUI Adapter 配置管理、Gateway OFF gate 和真实桌面客户端验收。

### 3.2 目标拓扑

    Antigravity MCP Host
      └─ starts AirBridge.exe mcp stdio
           stdin/stdout pipes
           └─ Agent context: antigravity
                └─ M2.4 Credential Provider
                     └─ Antigravity Agent Service Token
                          └─ existing AirBridge local API / Runtime

    OpenCode MCP Host
      └─ starts AirBridge.exe mcp stdio
           stdin/stdout pipes
           └─ Agent context: opencode
                └─ M2.4 Credential Provider
                     └─ OpenCode Agent Service Token
                          └─ existing AirBridge local API / Runtime

- MCP Client 和 STDIO 子进程运行在同一台 Windows 主机、同一目标 Windows 用户上下文。
- MCP Client 创建子进程及 stdin / stdout 管道；AirBridge 不监听 TCP 端口。
- Host A 与 Host B 不通过 MCP STDIO 相互连接。跨机器请求仍由 Agent 经现有 AirBridge Runtime / ABFP / 串口传输。
- A、B 可独立安装和配置本机 MCP Client Adapter；两台主机之间不交换 CA、证书或 MCP OAuth 状态。

## 4. 子进程入口与配置

### 4.1 统一 EXE 内部入口

目标内部入口建议为：

    AirBridge.exe mcp stdio

该入口已在 airbridge_entry.py 中实现：无参数启动调用 airbridge_app.run_gui()；精确参数 mcp stdio 才进入 MCP Server；其它以 mcp 开头的参数组合返回错误，不回退到 GUI。STDIO 分支在导入 MCP SDK 前不会导入 Qt / airbridge_app。

- MCP Adapter 通过客户端配置中的非秘密 AIRBRIDGE_AGENT_ID 环境变量标识本次子进程对应的已注册 Agent 实例；不将 Agent Token 放入环境变量。
- 子进程必须确认 Agent 实例存在、已启用、全局 Gateway 开关为 ON，并从 Credential Provider 读取该 Agent 自己的 M2.4 Service Token。
- Agent 不存在、已停用、没有凭据或凭据已撤销时，必须 fail closed，不得回退到另一个 Agent 的凭据。
- 命令行、MCP 配置和环境变量不得包含 Service Token、密码或其它秘密。

### 4.2 Antigravity 配置示意

    {
      "mcpServers": {
        "airbridge-antigravity": {
          "command": "C:\\Program Files\\AirBridge\\AirBridge.exe",
          "args": ["mcp", "stdio"],
          "env": { "AIRBRIDGE_AGENT_ID": "antigravity" },
          "disabled": true
        }
      }
    }

真实安装路径由 Adapter 发现，不假设固定安装目录。首次安装使用 disabled: true，Gateway 启用后才改为 false。

### 4.3 OpenCode V2 配置示意

    {
      "mcp": {
        "servers": {
          "airbridge-opencode": {
            "type": "local",
            "command": [
              "C:\\Program Files\\AirBridge\\AirBridge.exe",
              "mcp", "stdio"
            ],
            "environment": { "AIRBRIDGE_AGENT_ID": "opencode" },
            "disabled": true
          }
        }
      }
    }

真实安装路径由 Adapter 发现。首次安装 disabled: true；Gateway 启用后改为 false。

### 4.4 配置管理约束

- Antigravity 与 OpenCode 使用各自独立的 Adapter，不共享 JSON 模板。
- 自动修改仅限当前 Windows 用户级受支持配置；不得改动项目级 / 系统级配置。
- 写入前备份、解析、校验；原子替换；失败回滚。
- 只修改 AirBridge 自己拥有的条目，保留用户其它 MCP Server、JSON / JSONC 字段和格式语义。
- Adapter 必须幂等；重复安装 / 升级不能创建重复条目。
- 首次安装 Gateway OFF：配置条目可创建为 Disabled，也可按 Adapter 能力暂不创建；GUI 必须清晰显示，不能启动 STDIO 进程。

## 5. 认证与授权模型

STDIO 依赖本机 MCP Host 创建子进程并提供管道，不再引入网络层 OAuth。

### 5.1 保留 M2.4 Agent Service Token

- MCP Adapter 只在本机子进程环境中设置非秘密 AIRBRIDGE_AGENT_ID；不传入任何 Token。
- STDIO 子进程在启动时通过现有 Credential Provider / Windows Credential Manager 加载该 Agent ID 对应的 Service Token。当前 mcp_gateway/config.py 的 GatewayConfig.from_env 已有该加载路径，M2.5 应复用并纳入统一 EXE。
- Token 仅用于子进程 → AirBridge HTTP API 的现有 M2.4 认证路径。
- Token 不写入 MCP Client 配置、命令行、进程环境变量、stdout、stderr、普通日志或诊断包。
- M2.4 服务端继续实施 Scope、Agent 所有权、请求隔离、撤销、限流和审计。
- Agent ID、Credential、Scope 必须在服务端和 Credential Provider 端绑定；STDIO 请求参数不能临时指定或提高 Scope。
- Antigravity 子进程不能读取 OpenCode 凭据，反之亦然。

### 5.2 本机安全边界

- STDIO 子进程继承启动它的 Windows 用户身份；Credential Provider 按该用户身份读取凭据。
- 安全边界以 Windows 用户账户、AirBridge 安装目录 ACL、当前用户配置 ACL 和 M2.4 服务端授权为基础。
- STDIO 不是对同一 Windows 用户下恶意进程的独立身份认证，也不证明调用者品牌身份。不得宣称仅凭 STDIO pipe 能认证“这是 Antigravity 官方进程”。
- 同一用户修改本机 MCP 配置或直接运行本机 EXE，属于该 Windows 用户控制范围；M2.4 Service Token 的 Agent / Scope 权限仍必须由服务端校验。
- 不建立远程监听器，不因 MCP STDIO 接入增加 LAN / 防火墙暴露面。

### 5.3 STDIO 协议输出

- stdout 只能写 MCP stdio framing / JSON-RPC 消息，禁止写启动横幅、调试信息、普通日志或进度文本。
- 所有诊断与错误日志写 stderr 或 AirBridge 自己的受 ACL 保护日志文件。
- 正确处理 initialize、notifications、tools/list、Tool 调用、取消、EOF、broken pipe 和父进程退出。
- EOF / 管道关闭后有界退出，不得转为后台常驻进程或启动 TCP listener。
- 当前统一 EXE 保持 PyInstaller windowed / console=False，GUI 不产生控制台窗口。Windows windowed bootloader 会将 sys.stdin/stdout/stderr 置为 None；STDIO 入口通过 stdio_io.restore_windows_stdio() 从 MCP Host 通过 STARTF_USESTDHANDLES 传入的 GetStdHandle 句柄恢复 UTF-8 文本流，然后才导入 MCP SDK。
- 这项恢复只发生在 mcp stdio 分支，不影响 GUI 分支；任一继承句柄缺失或无效时 STDIO 启动 fail closed，不回退到无协议输出或网络 listener。

## 6. 生命周期与 GUI 职责

### 6.1 生命周期所有者

**MCP Host 是 STDIO 子进程的生命周期所有者。**

- Antigravity / OpenCode 在连接 MCP Server 时启动对应 AirBridge.exe 子进程。
- MCP Host 负责关闭管道、断开连接和结束子进程。
- AirBridge GUI 不启动、不停止、不重启由 MCP Host 创建的 STDIO 子进程；也不把客户端拥有的进程显示成 GUI Supervisor 拥有的 Worker。
- GUI 可通过受控诊断方式观察进程、最后连接时间和错误记录；观察结果不得表述为 GUI 拥有生命周期。
- 不允许创建长期驻留的 Gateway HTTP 服务或独立后台 Worker 来绕过 STDIO。

### 6.2 Gateway OFF 的强制语义

- 新安装 gateway.enabled=false；对应 MCP Host 配置保持 Disabled 或不安装。
- 用户关闭 Gateway 时，GUI 先持久化全局 OFF 状态，再把两个 Adapter 条目标为 Disabled。
- 每个 STDIO 子进程在每次 Tool 调用前检查当前全局开关、Agent 实例开关及凭据状态；关闭后立即拒绝新 Tool 请求，即使客户端尚未刷新配置或关闭已有子进程。
- GUI 提示用户按客户端支持方式 reload / restart MCP connection，以结束仍打开的 STDIO 子进程。AirBridge 不强杀 MCP Host 或其其它子进程。
- 用户重新启用时，GUI 在完成凭据和 Adapter 配置检查后更新 Disabled 状态；客户端重新连接后创建新的 STDIO 子进程。
- Gateway OFF 不撤销或删除 M2.4 Service Token，除非用户显式执行 Agent Credential revoke / remove。

#### 6.2.1 当前用户本机策略文件（已实现基础读写与执行门禁）

M2.5 统一 EXE 的策略文件位于：

`%LOCALAPPDATA%\\AirBridge\\gateway.json`

最小 schema：

```json
{
  "schema_version": 1,
  "enabled": false,
  "agents": {
    "antigravity": { "enabled": false },
    "opencode": { "enabled": false }
  }
}
```

约束：
- 文件缺失等同首次安装默认 OFF；缺少对应 Agent 项、策略文件不可读、JSON 损坏、schema 不支持或字段类型不正确均 fail closed。
- 仅存放非秘密开关状态；不存储 Agent Token、密码、Scope 凭据或 OAuth 信息。
- GUI 通过 `GatewayPolicyStore.write()` 更新完整策略快照；写入同目录临时文件、flush 后用 `os.replace` 原子替换，避免 STDIO 子进程读到半写文件。
- 统一 EXE 的 `mcp stdio` 入口内部设置 `AIRBRIDGE_M2_5_GATEWAY_POLICY=1`；该标记不是 MCP Client 配置项。M2.5 服务层在每次 Tool 调用前重新读取策略，然后才可能调用现有 AirBridge HTTP API。
- 同一 MCP 子进程保持运行期间，GUI 将全局 Gateway 或某 Agent 改为 OFF 后，下一个 Tool 请求立即被拒绝；不依赖客户端是否已 reload / restart。
- 该门禁不撤销 M2.4 Credential。M2.4 API 每次请求仍验证 Agent Service Token 的服务器端 enabled / revoked 状态、Scope、所有权和限流；Token 被撤销后，已运行的 MCP 子进程也不能继续访问 API。
- 为保持 M2.1 / M2.2 独立 Python 包的历史兼容，策略强制由统一 AirBridge.exe 的 M2.5 STDIO 入口启用；M2.5 Adapter 不得再生成或启动旧独立虚拟环境 Gateway。

### 6.3 不再适用的生命周期设置

- gateway.start_with_airbridge 不再控制 STDIO 子进程启动；它们由 MCP Host 管理。
- 不显示 Broker / Worker 持久服务、端口、listener、PID 存活保证或 Supervisor shutdown 状态。
- GUI 关闭不负责关闭仍由 Antigravity / OpenCode 使用的 STDIO 子进程；子进程在 MCP Host 关闭管道 / 断开后退出。
- 双机 Gateway ON / OFF 状态交换可保留，但含义是“本机 MCP Adapter 是否启用”，不是“本机 HTTP 服务是否正在监听”。

## 7. GUI 管理状态

Gateway 总览至少区分：
- Gateway 配置：ON / OFF；
- Agent Adapter：Installed / Disabled / Enabled / Configuration Error；
- Agent Credential：Present / Missing / Revoked / Scope mismatch；
- MCP Host：Detected / Not detected / Version unsupported；
- STDIO 连接：Connected（有真实握手证据）/ Disconnected / Unknown；
- 最近一次 MCP initialize、tools/list 和 Tool 请求的时间与结果；
- 最近错误及 stderr 日志位置。

**Configured / Enabled 不等于 Connected。** 如果 MCP Host 不提供可验证的连接状态，GUI 显示 Unknown / Not observed，不推断为 Running。

## 8. 被取消的网络与证书设计

以下全部从 M2.5 首版移除：
- https://localhost:<port>、OAuth Broker 38861、Antigravity Worker 38862、OpenCode Worker 38863 等 endpoint / port；
- Streamable HTTP、SSE、WebSocket；
- CurrentUser Root CA bootstrap、证书生成、安装、更新、轮换、撤销和卸载；
- CryptUIWizImport 交互式证书向导和 G-01B；
- G-01 Windows CurrentUser HTTPS trust-scope / chain CI；
- OAuth Authorization Server / Resource Server、PKCE、CIMD、DCR、Grant、Refresh Token、Resource Audience 和 OAuth Consent；
- Self-hosted Windows Runner、桌面证书交互验收及任何跨机器 HTTPS 设计。

不需要为了 STDIO 建立 GitHub Windows 桌面 Self-hosted Runner。普通 GitHub Actions 可运行协议 framing、配置适配、进程入口和权限隔离自动化测试；实际 Antigravity / OpenCode 桌面客户端兼容性在已有目标 Windows 桌面环境完成端到端验收即可。

## 9. GitHub Actions 与真实客户端验收

### 9.1 自动化 CI

- Antigravity / OpenCode 配置生成、解析、更新、回滚和幂等性；
- STDIO initialize / tools/list / Tool call / notifications / cancellation / EOF / broken pipe；
- stdout 纯净性：任何非 MCP 输出都使测试失败；
- M2.4 Credential Provider 测试替身：正确 Agent 读取正确测试 Credential；缺失 / 撤销 / 错误 Agent / Scope 不足均 fail closed；
- Gateway 全局 OFF、Agent OFF、凭据撤销后，存量 STDIO 进程的新 Tool 调用被拒绝；
- MCP Host 退出或关闭管道后子进程有界退出，无后台孤儿进程；
- 子进程不监听 TCP 端口；
- AirBridge.exe 以 Python 3.11+、MCP SDK mcp==2.3.0 和锁定 PyInstaller 构建；同一个 onefile EXE 由 airbridge_entry.py 分流 GUI 与 STDIO。
- GitHub Actions 对 windowed 冻结 EXE 使用真实子进程和三个继承管道执行 initialize / tools/list；MCP 子进程必须只向 stdout 输出协议消息。
- Windows Python 3.10 / 3.11 / 3.12 现有 Capture Process Inventory 回归继续运行；产品统一运行时仍按 M2.5 Python 3.11+ 要求迁移和验证。

### 9.2 桌面客户端验收

在实际目标 Windows 桌面系统上分别验证冻结版本：
- Antigravity App / IDE 使用本机 STDIO entry 启动 AirBridge.exe；
- OpenCode Desktop / CLI（首版支持矩阵明确具体形态）使用 local / command entry 启动同一 AirBridge.exe；
- initialize、tools/list、只读 Tool 调用完成；
- 两个 Adapter 各自加载正确 Agent ID 和 Credential；
- Gateway OFF、Agent OFF、Credential revoke 后请求被拒绝；
- 客户端 reload / exit 后 STDIO 子进程退出；
- 不创建监听端口，不安装或修改任何证书。

## 10. 迁移与版本兼容

- 复用当前 main 的 mcp_gateway/airbridge_mcp_gateway STDIO Server、AirBridgeGateway、WindowsCredentialStore 和已有单元测试；不要另建第二套 MCP Server 实现。
- 将 STDIO 入口和 MCP SDK 依赖整合进统一 AirBridge.exe / Python 3.11+ 构建；首版正式 Adapter 不再要求安装独立 Python 虚拟环境或单独 Gateway 包。
- AIRBRIDGE_AGENT_ID 是允许传入的非秘密 Agent 标识；AIRBRIDGE_AGENT_TOKEN 属于旧式兼容路径，不得由 M2.5 Adapter 新生成或写入配置。
- M2.5 首版不提供 Remote / HTTP MCP Adapter。
- 从旧设计或测试分支迁移时，删除 AirBridge 自己生成的 OAuth / HTTPS MCP 条目和证书管理状态；不得删除用户其它证书、其它 MCP Server 或客户端自己的 OAuth Vault。
- 如果现有配置中存在旧版 AirBridge HTTPS 条目，Adapter 只识别和迁移精确归属于 AirBridge 的条目；先备份并展示变更摘要。
- 不读取、复制、清理或修改 Antigravity / OpenCode 私有 OAuth Token Vault；STDIO 不使用这些远程 OAuth Token。
- AirBridge HTTP API、M2.4 凭据数据库、Agent ID、Scope、审计记录和既有 A/B 串口通信按各自迁移规则保留。

## 11. 验收与 Go / No-Go

- [ ] Antigravity 官方本机 STDIO 配置在目标 App / IDE 版本上成功启动统一 AirBridge.exe。
- [ ] OpenCode 官方 local / command 配置在目标 Desktop / CLI 版本上成功启动统一 AirBridge.exe。
- [ ] 两个客户端完成真实 initialize、tools/list 和只读 Tool 调用。
- [ ] stdout 无任何非 MCP 内容，stderr / 文件日志不污染协议。
- [ ] Agent ID 与 Credential / Scope 精确绑定；两个 Agent 凭据不可互换。
- [ ] 缺少、错误、撤销的 Credential 和 Scope 不足均 fail closed。
- [ ] Gateway OFF / Agent OFF 后存量子进程不能继续执行 Tool。
- [ ] Host reload / exit 后子进程退出，无后台孤儿和 TCP listener。
- [ ] 配置 Adapter 更新幂等，保留用户其它 MCP 条目，失败可回滚。
- [ ] 不新增证书、TLS、OAuth Broker、端口或网络 MCP endpoint。
- [ ] GitHub Actions 相关自动化门禁通过；目标 Windows 客户端手工验收有版本、日志和结果记录。

若任何目标客户端不支持本机 STDIO、不能安全访问该 Windows 用户的 M2.4 Credential Provider，或子进程无法满足 fail-closed / 有界退出要求，暂停该客户端 Adapter 验收并重新评审；不得自行回退到 HTTP / HTTPS、证书或 OAuth Broker。
