## 1. 本阶段目标

在 Capture Skill 内实现一个最小的工程打开与只读查询能力：

1. 仅接受用户指定的 Host-B 绝对 `.opj` 路径；
2. 经通用 AirBridge Shell 在 Host B 检查文件存在、类型、长度和最后写入时间；
3. 检查当前 Capture Tcl Session 的活动 Design；
4. 如果已存在活动 Design，拒绝切换或接管；
5. 只有显式用户授权后才通过现有 M3.2.4 Tcl 队列执行 `Open <opj>`；
6. 在同一 Request 中读取 Dbo Active Design 与 Project Manager Active Design；
7. 只有对象身份一致、Capture PID / Tcl 版本匹配 READY Manifest，才记录为 opened；
8. 提供 DBO-V02：枚举当前 Session 中已经加载的 Design 和 Library，不加载新对象。

本阶段不增加任何 AirBridge Core / ABFP / HTTP EDA 专用接口。Host A 与 Host B 仍运行同一个 AirBridge.exe，所有远端操作使用通用 Shell / RFS。

## 3. OPJ 打开流程

完整顺序：

1. 验证 `user_authorized is True`，否则无 Shell / Tcl 副作用；
2. 验证路径是绝对 Windows 路径且扩展名为 `.opj`；
3. 检查本 Session 是否已有 Design Context；若有则拒绝再次 Open；
4. 通过当前 Tcl Bridge 读取活动 Design；如果存在活动 Design，则拒绝切换；
5. 使用通用 Shell 在 Host B 运行 `Get-Item -LiteralPath`，确认是非目录、非空 OPJ 文件；
6. 在 Host A 本地以独占创建方式写入 Design Context，记录原始 Request ID 和 OPJ 元数据；
7. 使用现有 `CaptureTclQueue.execute()` 发送 Tcl `Open` 请求；
8. 同一 Tcl 请求内读取 `$session GetActiveDesign` 和 `GetActivePMDesign`，记录对象名称和指针相等性；
9. 检查 Dbo / Project Manager 均为非 NULL、对象指针一致，并核对 Tcl PID / 版本；
10. 验证通过后将本地 Design Context 标记为 `opened`。

OPJ 路径先 Base64 编码再在 Tcl 内解码为变量，绝不拼接成可解释的 Tcl 命令文本。工程文件留在 Host B，不下载到 Host A。

## 4. 已有活动设计与 UNKNOWN

本 Skill 每个 Capture Session 只允许一个 Design Context。若发现已有活动 Design，不会自动关闭、切换或接管，也不会调用第二次 `Open`。

Open 前先持久化本地 Design Context 和 Request ID。遇到响应丢失、队列 UNKNOWN 或结果信封不能验证时：

- Design Context 标为 `unknown` 或 `verification_failed`；
- 禁止再次调用 `Open`；
- 只允许通过原始 Request ID 调用现有 Tcl queue 的只读 `reconcile()`；
- 原始结果可验证且原 Capture 进程身份匹配后，才可将 Context 标记为 `opened`；
- 没有原始结果或对象身份不匹配时，保持未决，不自动重发。

## 5. Dbo API 范围

### Active Design 验证

读取：

- `::DboSession_s_pDboSession`
- `DboSession -this $session`
- `$session GetActiveDesign`
- 在 Active Design 非 NULL 时读取 `GetActivePMDesign`
- 两个对象指针是否一致；
- 使用 `DboTclHelper_sMakeCString` / `DboTclHelper_sGetConstCharPtr` 读取 Design 名称。

Start Page 状态只依赖已经在 Capture 17.2 / Tcl 8.6 实测的 `GetActiveDesign -> NULL` 行为。没有活动 Design 时不再调用 Project Manager 对象 API。

### DBO-V02：当前 Session 对象枚举

只调用文档示例已使用的 API：

- `NewDesignsIter` / `NextDesign`
- `NewLibsIter` / `NextLib`
- `GetName` + CString Helper
- `delete_DboSessionDesignsIter`
- `delete_DboSessionLibsIter`
- `DboState -delete`

枚举结果仅代表当前 Session 已加载的对象，不是磁盘上的全部 DSN / OLB 文件。

### 明确禁止

本阶段不调用：

- `GetDesign` / `GetDesignAndSchematics` / `GetLib` 等可能加载对象的方法；
- `SaveDesign` / `SaveDesignAs` / `SaveLib`；
- `RemoveDesign` / `RemoveLib`；
- `SetEffectivePropStringValue` / `SetDisplayProp`；
- `MarkModified` / `MarkAllLibForSave`；
- `Exit`、关闭窗口、终止或强杀 Capture。

### 6.1 Host B 实际验收（2026-11-19，集成验收）

M3.2.5 的 Host B 实际验证随 M3.2.6 集成验收完成，环境为 Windows + Cadence SPB 17.2，Capture 17.2-2016，Tcl 8.6.0。真实场景验证了：

- Host B OPJ 文件预检通过，用户明确授权后成功打开 `E:\_airbridge_temp\RK3588_PDF_Output\RK3588_WX8116-SCH-V2T.OPJ`；
- Dbo Active Design 与 Project Manager Active Design 均指向 `RK3588_WX8116-SCH-V2T.DSN`，对象身份比较 `same_design_object=true`；
- Dbo 当前 Session 清单返回 1 Design、0 Libraries；
- Design / Library 迭代器均到达 NULL 结束标志；Design Iterator、Library Iterator 和 DboState 资源释放返回码均为 0；
- 最终 `inventory_complete=true`、`resources_released=true`。

上述真实验收的 Session ID、Capture PID、Request ID 与后续两阶段退出证据见 [M3.2.6 实施记录](M3.2.6_Capture_授权退出与进程确认_实施记录.md)。这证明所列 OPJ / Dbo 路径在该 Capture 17.2 环境和该设计文件上通过，不代表所有 Cadence SPB 版本或所有设计对象结构均已验证。
