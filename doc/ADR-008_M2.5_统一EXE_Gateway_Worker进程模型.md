# ADR-008：M2.5 统一 AirBridge.exe 的 Gateway Worker 进程模型

> **架构更新（2026-11-20）：** 原文描述的 GUI Supervisor 拥有并启停持久 Gateway Worker 的模型不再适用于 M2.5 首版。现由 Antigravity / OpenCode MCP Host 启动并管理 AirBridge.exe STDIO 子进程；GUI 管理配置、Agent、Credential 和状态，不拥有该子进程生命周期。以 ADR-013 为准。


- 状态：**提议采用，必须经 Windows frozen EXE 原型验证**
- 日期：2026-11-20
- 决策范围：Windows / PyInstaller onefile / Gateway Worker lifecycle
- 关联：M2.5 统一运行时与 Gateway GUI 管理架构

## 1. 背景

主机 A / B 必须使用完全相同的 AirBridge.exe 和同一安装包。Gateway 需要在 GUI 中由 Supervisor 启停和监控，且不同 Agent 的身份、凭据和运行状态必须隔离。

目前仓库的 `AirBridge.spec` 以 `airbridge_app.py` 为入口，尚未实现同 EXE Gateway Worker 内部入口，也没有完成 Python 3.11+ 全产品统一打包。

## 2. 决策提议

采用一个统一 EXE，支持多个内部启动模式：

- GUI 主进程：默认启动桌面 UI 和本机 AirBridge 服务；
- Gateway Worker：根据显式参数进入内部 Worker 入口，不初始化 GUI；
- 未来其他内部进程模式如需增加，必须通过明确参数分派，不能让普通启动流程猜测角色。

每个 Agent 一个 Gateway Worker 进程，以固定身份隔离：
- `antigravity` Worker 只读取 Antigravity 对应凭据；
- `opencode` Worker 只读取 OpenCode 对应凭据；
- 不接受来自 MCP 请求的 agent_id 动态切换；
- 每个 Worker 有独立 PID、endpoint、端口、日志和健康状态。

概念命令：

```powershell
AirBridge.exe --gateway-worker --agent-id antigravity
AirBridge.exe --gateway-worker --agent-id opencode
```

命令仅用于说明内部入口，不是当前已实现接口。正式命令必须由 Supervisor 生成，且不能包含 Token、密码或其他秘密。

## 3. PyInstaller onefile 的重要约束

PyInstaller 官方文档说明：
- onefile 启动时会先解包到临时目录，再启动应用进程；
- 通过 `sys.executable` 启动独立的同 EXE 进程时，如果子进程需要在父应用退出后继续运行，不能复用父进程的临时解包目录；
- PyInstaller 6.9 起引入独立实例环境重置行为，spawn 一个可独立于父应用存活的实例时，应在子进程环境中设置 `PYINSTALLER_RESET_ENVIRONMENT=1`。

因此推荐由 Supervisor 使用 `subprocess.Popen([sys.executable, ...])` 启动内部 Worker，并为独立 Worker 设置：

```python
worker_env = os.environ.copy()
worker_env["PYINSTALLER_RESET_ENVIRONMENT"] = "1"
```

Worker 应作为独立 onefile 实例解包并运行，不能依赖 GUI 主进程即将清理的 `_MEIPASS` 临时目录。

该行为需要使用 M2.5 实际构建的 AirBridge.exe 在 Windows CI / 实体 Windows 环境中验证。不能仅凭 Python 源码运行通过就判定 frozen Worker 可用。

PyInstaller 官方资料：
- https://pyinstaller.org/en/latest/common-issues-and-pitfalls.html
- 其中 “Using sys.executable to spawn subprocesses that outlive the application process / Implementing application restart” 说明独立实例环境重置要求。

## 4. 进程入口分流

启动入口必须在 GUI / Qt 初始化和 AirBridge 全局服务启动前解析：

```text
AirBridge.exe
  ├─ 默认参数 → GUI Main
  ├─ --gateway-worker → Gateway Worker Main
  └─ 其他内部模式 → 对应 Worker Main（未来需要时）
```

约束：
- Gateway Worker 不创建第二个桌面窗口；
- Worker 运行路径不得启动新的 GUI、串口连接或重复创建 AirBridge Core HTTP Server；
- Worker 只访问既有 AirBridge HTTP API；
- Gateway OFF 时 Supervisor 不启动 Worker；
- 两端 EXE 中都必须包含 Gateway Worker 代码和依赖；
- 不允许构建时按 A/B 角色排除 Gateway 模块。

若未来使用 Python multiprocessing，必须按 PyInstaller 要求在相关启动路径尽早调用 `multiprocessing.freeze_support()`，避免 frozen child 参数重新进入 GUI 初始化路径。当前长生命周期 Gateway Worker 优先使用显式 subprocess 入口，不以 multiprocessing Pool 作为服务管理器。

## 5. Supervisor / Worker 控制通道

建议采用 Windows Named Pipe 作为 GUI Supervisor 到 Worker 的本机控制通道，访问 ACL 限定当前 Windows 用户 SID，并在创建时绑定随机启动 nonce。

控制消息至少包括：
- Worker READY；
- Health / Status；
- Graceful Shutdown；
- Drain Progress；
- Shutdown Result；
- Worker Failure / Exit Summary。

约束：
- 控制通道不得传递 Agent Service Token 明文；
- Worker 启动参数不得包含凭据；
- PID 不能单独作为 Worker 身份证明；Supervisor 应联合验证进程映像路径、创建时间、Agent ID、启动 nonce 和控制通道握手；
- Named Pipe ACL 是本机管理边界之一，不应被描述为抵御同一用户下恶意代码的沙箱；
- 日志通道必须脱敏。

Named Pipe 的具体协议、恢复状态文件和 Windows ACL 测试作为 M2.5.2 实施设计补充。

## 6. 生命周期

### 启动
1. GUI 读取有效配置；
2. 验证 Gateway 总开关、Agent 开关、凭据和端口；
3. 为每个 Agent Worker 生成启动 nonce；
4. Supervisor 使用同一个 AirBridge.exe 路径启动 Worker；
5. Worker 通过独立 onefile 实例启动；
6. Worker READY 后回报 PID、Agent ID、版本、endpoint；
7. Supervisor 验证进程身份并完成健康检查后标记 RUNNING。

### 正常停止
1. Supervisor 禁止新建 Worker 请求；
2. 通知 Worker 开始排空；
3. 在有界时间内等待在途请求；
4. MCP Server / HTTP 服务完成正常 shutdown；
5. Worker 回报 STOPPED 并退出；
6. Supervisor 确认真实进程退出后更新 GUI 状态。

排空超时不得谎报成功，也不得把强制 TerminateProcess 作为普通关闭方式。

### GUI 异常退出
- Worker 必须能够检测它所依附的 Supervisor GUI 进程已退出；
- Worker 按已定义的有界排空策略自行关闭；
- 下次启动 AirBridge GUI 时扫描并核对遗留 Worker 记录；
- 无法验证身份的进程不得被认领或控制；
- 不因 PID 被系统复用而误识别进程。

是否由 GUI 退出即终止 Worker，作为产品默认策略写入 M2.5 配置；初版建议 GUI 退出时有序停止所有 Worker，不提供未受控的后台孤儿运行。

### 升级期间的 Worker 生命周期
- 安装器 / 升级协调器先请求 Supervisor 有界排空并停止所有受管 Worker，再迁移运行配置；不得让旧版与新版 Worker 同时占用相同 Agent endpoint 或访问同一 Grant Store。
- 升级前后保留稳定的 Agent instance ID、Worker 端口 / endpoint 和 enabled 配置；版本升级本身不改变用户开关。
- 只有在配置 / Broker 数据迁移提交成功、Worker binary 与持久化 schema 兼容且健康检查通过后，才按保存的 Gateway / Agent 开关恢复 Worker。
- 迁移失败或状态不确定时，Worker 保持停止；不得通过自动重置配置恢复启动。GUI 显示错误并提供备份恢复路径。
- 进程关闭 / 重启不得删除 Agent Credential、OAuth Grant、证书或用户配置。

### 端口分配与监听
- Local OAuth Broker 默认监听 TCP 38861；首个 Antigravity Worker 默认 TCP 38862；首个 OpenCode Worker 默认 TCP 38863。
- 默认候选端口池为 TCP 38801–38864；新增 Agent 实例使用池内唯一空闲端口，并将分配值持久化。Broker 与所有 Worker 端口不得重复。
- 端口仅绑定 loopback（IPv4 127.0.0.1 / IPv6 ::1，按平台支持情况），不得绑定通配地址；客户端 URL 固定使用 `localhost`。
- Supervisor 启动前校验配置端口，并以实际 socket bind 作为最终占用检查；同时读取系统当前动态端口 / excluded port range。PID / 进程名仅作为诊断信息，不能替代 bind 检查。
- 冲突时不启动冲突服务、不静默改随机端口；Broker 不可用则依赖 Broker 的 Managed HTTPS OAuth Worker 不得标记为健康，单个 Worker 冲突不应连带停止其它独立 Worker。
- 用户修改端口必须先完成端口可用性验证，再同步 Resource / issuer metadata 与 Adapter 管理的当前用户级 MCP Client endpoint 配置；更新失败回滚，不能留下半迁移状态。
- Worker port 变化导致 Resource Audience 变化，需重新授权；Broker port 变化导致 issuer 变化，需重新 discovery / OAuth 授权。证书 SAN 不包含端口，但 hostname 必须仍与证书匹配。

## 7. 日志、健康与状态

每个 Worker 至少暴露：
- PID / process creation time；
- executable path / file version；
- Agent ID；
- transport / bind endpoint / port；端口配置值、冲突状态、实际绑定地址与端口必须可观测；
- started_at / uptime；
- health state；
- last error / exit code；
- configuration generation / launch nonce。

Supervisor 区分：
- 配置已启用；
- 正在启动；
- 运行中且健康；
- 运行中但降级；
- 正在停止；
- 已停止；
- 启动失败 / 异常退出。

GUI 的状态不能只依据 `enabled=true` 推断。

## 8. 安全约束

- Worker 启动参数只允许非秘密配置，如 Agent ID、端口和启动 nonce；
- 不能用命令行传递 Token、密码或完整凭据；
- Worker 仅能加载与自身固定 Agent ID 对应的 Windows Credential Manager 凭据；
- 每个 Worker 必须有独立的进程级配置上下文；
- 不允许所有 Worker 共享一个可变的全局 Agent ID；
- 关闭/崩溃恢复不得删除其他 Agent Worker 的凭据；
- 一个 Worker 崩溃不得导致另一个 Worker 被错误停止或改写状态。

## 9. 验收

- [ ] GUI 和 Worker 的 `sys.executable` / 映像路径均指向同一个 AirBridge.exe 文件。
- [ ] Worker 模式不创建 GUI 窗口。
- [ ] Worker 使用 Python 3.11+ 内置运行时。
- [ ] onefile Worker 设置独立实例环境，GUI 退出或崩溃时不依赖 GUI 的临时解包目录。
- [ ] Worker READY 报告的 PID 与真实进程映像、创建时间一致。
- [ ] Antigravity / OpenCode Worker 的 Agent ID 和凭据固定、互相隔离。
- [ ] GUI 启动、停止、重启和排空行为真实可观察。
- [ ] GUI crash 后 Worker 自行有界退出，不留下孤儿服务。
- [ ] Worker crash 不影响 AirBridge Runtime / 串行通信。
- [ ] 日志、命令行和普通配置不含秘密。
- [ ] Python 3.11+ 构建与既有 M1 / M2 回归通过。
